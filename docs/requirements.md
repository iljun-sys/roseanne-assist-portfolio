# 로즈앤 어시스트 — 요구사항 정의서

| 항목 | 내용 |
| --- | --- |
| 문서명 | 로즈앤 어시스트(RoseAnne Assist) 요구사항 정의서 |
| 버전 | v1.0 |
| 작성일 | 2026-08-10 |
| 작성 방식 | **역공학(Reverse-engineering)** — 선행 요구사항 정의 없이 개발된 시스템의 코드·DB 스키마·개발 로그(≈130건)를 근거로 사후 정리 |
| 대상 시스템 | 로즈앤의원 환자 예진 + 진료 어시스트 |

> ⚠️ 이 문서는 **"현재 무엇이 만들어져 있는가"를 요구사항 형태로 재구성**한 것이다. 각 요구사항에는 실제 구현 상태(✅ 구현 / ⚠️ 부분 / ❌ 미구현)를 표기해, 앞으로의 개발에서 기준선(baseline)으로 쓸 수 있게 했다.

## 1. 시스템 개요

### 1.1 목적
산부인과·검진·여성성형을 진료하는 단일 의원(로즈앤의원)에서

1. 환자가 **대기 중 태블릿으로 예진(문진)** 을 마치고
2. 스태프가 **접수·확인 후 담당 원장에게 배정**하며
3. 원장이 **AI가 정리한 브리핑을 보고 진료**하고
4. 진료 후 **환자가 이해할 수 있는 안내문**을 전달하는

일련의 흐름을 하나의 웹 앱으로 지원한다.

### 1.2 해결하려는 문제
| # | 문제 | 대응 |
| --- | --- | --- |
| P-1 | 종이 문진표는 판독·입력에 시간이 들고 누락이 잦음 | 태블릿 디지털 예진 |
| P-2 | 원장이 짧은 진료시간에 문진 내용을 모두 파악하기 어려움 | AI 브리핑·SOAP 자동 생성 |
| P-3 | 진료 내용을 환자가 이해하지 못한 채 귀가 | 쉬운 말 안내문(인쇄) |
| P-4 | 대기 현황·배정 상태가 한눈에 안 보임 | 칸반형 실시간 현황판 |
| P-5 | 진료 기록 정리(SOAP·EMR 입력) 부담 | 음성 녹음 → 자동 요약 |

### 1.3 사용자 역할

| 역할 | 인증 | 주요 행위 |
| --- | --- | --- |
| **환자** | 없음(익명 `anon`) | 태블릿에서 예진 작성·제출 |
| **스태프**(간호/데스크) | 계정 로그인 | 접수 확인, 문진 수정, 원장 배정, 현황 관리 |
| **원장**(의사) | 계정 로그인 | 진료, AI 브리핑/SOAP 확인, 음성 녹음, 환자 안내문 확정 |
| **마스터 관리자**(superadmin) | 계정 로그인 | 전 페이지 접근, 원장 계정 생성/비활성, 가입 승인 |

## 2. 업무 흐름 (As-Is)

```
[환자] 태블릿 예진 작성 ──▶ 제출(익명)
            │
            ▼
[스태프] 오늘 현황(칸반) — 미배정 열에 도착
            │  ├ 문진 내용 확인 / 필요시 수정
            │  └ 담당 의사 배정
            ▼
[원장] 대기중 → 진료중 → 완료
            │  ├ AI 브리핑 / SOAP 확인
            │  ├ 진료 메모(자동저장)
            │  └ 음성 녹음 → 자동 요약(동의 시)
            ▼
[원장] 환자 안내문: AI 초안 ─▶ 의사 확인·수정 ─▶ 확정 ─▶ 인쇄
            ▼
[시스템] 자정 경과 시 미완료 방문 자동 완료 처리
```

## 3. 기능 요구사항 (FR)

### FR-1. 환자 예진 (문진표)

| ID | 요구사항 | 우선순위 | 상태 |
| --- | --- | --- | --- |
| FR-1.1 | 환자는 **로그인 없이** 태블릿에서 예진을 작성할 수 있어야 한다 | 필수 | ✅ |
| FR-1.2 | 방문 목적을 **복수 선택**할 수 있어야 한다 (산부인과 / 검진 / 여성성형·시술 / 재방문) | 필수 | ✅ |
| FR-1.3 | 선택한 방문 목적에 따라 **문항이 동적으로 분기**되어야 한다 | 필수 | ✅ |
| FR-1.4 | 기본정보(성명·성별·생년월일·연락처·방문일)를 입력받는다 | 필수 | ✅ |
| FR-1.5 | 산부인과: 증상 카테고리(생리/분비물/통증/임신·피임/갱년기/기타) 및 세부 증상을 선택한다 | 필수 | ✅ |
| FR-1.6 | 갱년기 선택 시 **KI(Kupperman Index) 자가 점검표**를 제공하고 점수를 산출한다 | 필수 | ✅ |
| FR-1.7 | 검진: 검사 항목(자궁경부세포·액상세포·HPV·확대촬영·STD 등)을 선택한다 | 필수 | ✅ |
| FR-1.8 | 성형·시술: 희망 시술(소음순성형·질레이저·금실·제모 등)을 선택한다 | 필수 | ✅ |
| FR-1.9 | 과거력·복약·알레르기·수술력·흡연·초음파/자궁경부암 검사 이력을 수집한다 | 필수 | ✅ |
| FR-1.10 | **미성년자**는 보호자 정보를 입력받되, 프라이버시 사유의 **건너뛰기**를 허용한다 | 필수 | ✅ |
| FR-1.11 | 개인정보 수집·이용 **동의 및 전자 서명**을 받는다 | 필수 | ✅ |
| FR-1.12 | **AI 녹음 동의**를 별도로 받는다(미동의 시 녹음 기능 차단) | 필수 | ✅ |
| FR-1.13 | 비급여 치료 선호도를 선택받는다 | 선택 | ✅ |
| FR-1.14 | 재방문은 단독 플로우(재방문 유형 → 메모 → 동의)로 처리한다 | 필수 | ✅ |
| FR-1.15 | 제출 실패 시 **성공으로 오인되지 않아야** 한다 | 필수 | ✅ ※1 |
| FR-1.16 | 다국어(한/영/중/일)를 지원한다 | 선택 | ❌ 미구현 (스키마 `patients.language`만 존재) |

> ※1 과거 anon 쓰기가 RLS에 막혀 임상 데이터가 조용히 유실되고 성공 처리되던 결함이 있었음(2026-06-05 수정). 현재는 실패를 수집해 `success:false`로 반환.

### FR-2. 접수·배정 (스태프)

| ID | 요구사항 | 우선순위 | 상태 |
| --- | --- | --- | --- |
| FR-2.1 | 오늘 접수된 환자를 **칸반 보드**(미배정 / 원장별 열)로 표시한다 | 필수 | ✅ |
| FR-2.2 | 미배정 환자를 드롭다운으로 **담당 의사에게 배정**할 수 있어야 한다 | 필수 | ✅ |
| FR-2.3 | 환자 카드에서 상태(대기중/진료중/완료)를 직접 변경할 수 있어야 한다 | 필수 | ✅ |
| FR-2.4 | 배정된 환자를 **다른 원장으로 이관**할 수 있어야 한다 | 필수 | ✅ |
| FR-2.5 | 카드는 **진료중 → 대기중 → 완료** 순으로 정렬한다 | 필수 | ✅ |
| FR-2.6 | 카드에 **접수 후 경과시간(분)** 을 표시하고, 10분 단위로 색을 단계화하며 60분 이상은 긴급 강조한다 | 필수 | ✅ |
| FR-2.7 | 카드에 방문 목적·주요 증상을 **태그**로 요약 표시한다 | 필수 | ✅ |
| FR-2.8 | 현황은 **주기적으로 자동 갱신**된다 (폴링 10초) | 필수 | ✅ |
| FR-2.9 | 스태프는 제출된 문진 내용을 **수정**할 수 있어야 한다 | 필수 | ✅ |
| FR-2.10 | 날짜 범위·방문유형·환자 이름으로 **과거 예진 데이터를 조회**할 수 있어야 한다 | 필수 | ✅ |

## 4. 데이터 요구사항

### 4.1 주요 엔티티
| 엔티티 | 역할 |
| --- | --- |
| `patients` | 환자 마스터(이름·생년월일·성별·연락처·미성년 여부·EMR 연계 필드) |
| `visits` | 1회 방문(상태·담당의·동의·서명·자동완료·EMR 연계) |
| `visit_examinations` | 방문별 예진 섹션 데이터 (`gynecology` / `cosmetic` / `screening` / `menopause_ki`) |
| `visit_symptoms` | 선택한 증상 |
| `visit_health_info` / `visit_medical_conditions` | 건강정보 / 기저질환 |
| `visit_guardians` | 미성년자 보호자 |
| `visit_ai_results` | AI 브리핑·SOAP·전사문·사용 모델 |
| `visit_consultations` | 진료 메모·음성 요약·환자 안내문 확정본 |
| `visit_summaries` | 진료요약 발송 워크플로(승인·발송·열람 상태) |
| `users` / `doctor_profiles` | 계정·역할·승인 / 원장 프로필 |

### 4.2 상태 전이 (visit_status)
```
대기중 ──▶ 진료중 ──▶ 완료
   └──────────────────▶ 취소
   (자정 경과 시 대기중/진료중 → 완료, auto_completed=true)
```

### 4.3 설계 규약 (반드시 유지)
| 규약 | 내용 |
| --- | --- |
| **방문유형 표기** | `visits.visit_type`은 **항상 `복합`** 으로 기록하고, 실제 선택 섹션은 `visit_examinations` 행으로 표현한다. 읽을 때도 `visit_examinations`에서 유도한다 |
| **한국어 enum** | DB enum은 한국어(`대기중`·`여성` 등), UI는 영어 키. 변환은 `src/lib/visitStatus.ts`에 집중 |
| **KI 저장 위치 이중성** | 갱년기 KI는 독립 행 또는 산부인과 exam의 `data.menopause_ki` 내부 양쪽에 존재 가능 → 읽기 로직이 둘 다 처리해야 함 |

## 5. 비기능 요구사항 (NFR)

### 5.1 보안·개인정보
| ID | 요구사항 | 상태 |
| --- | --- | --- |
| NFR-1.1 | 모든 테이블에 **RLS(행 수준 보안)** 를 적용한다 | ✅ |
| NFR-1.2 | 익명(anon) 환자는 **자신이 방금 생성한 미배정 방문에만** 쓰기가 가능하다 | ✅ |
| NFR-1.3 | 서비스 롤 키는 **서버·엣지 함수 환경변수에만** 두고 클라이언트에 노출하지 않는다 | ✅ |
| NFR-1.4 | 모든 엣지 함수는 **호출자 인증·역할 검증**을 수행한다 | ✅ (2026-08-10 적용) |
